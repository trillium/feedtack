This guide walks through a production-ready Feedtack setup with a Next.js API route, Zod validation, and rate limiting.

## 1. Install Feedtack

```bash
pnpm add feedtack
```

    id: z.string(),
    name: z.string(),

  }),
  comment: z.string().min(1).max(5000),
  sentiment: z.enum(["good", "bad"]).nullable(),
  pins: z.array(z.any()),

## 3. Wire up the provider

```tsx
// app/layout.tsx or providers/FeedtackProvider.tsx
"use client";

import { FeedtackProvider } from "feedtack/react";
import { WebhookAdapter } from "feedtack";

const adapter = new WebhookAdapter({
  submitUrl: "/api/feedtack",
  loadFeedback: async (filter) => {
    const res = await fetch(`/api/feedtack?pathname=${filter?.pathname ?? ""}`);
    return res.json();
  },
});

export function FeedtackWrapper({ children, user }: { children: React.ReactNode; user: any }) {
  return (
    <FeedtackProvider
      adapter={adapter}
      currentUser={user}
      adminOnly
      onError={console.error}
    >
      {children}
    </FeedtackProvider>
  );
}
```

## 4. Gate visibility

Use `adminOnly` to restrict the feedback button to admin users. Non-admin users won't see the button, but they can still use the `useFeedtack` hook if you build custom UI for them.

For more granular control, conditionally render the provider:

```tsx
{user.role === "admin" || user.role === "designer" ? (
  <FeedtackProvider adapter={adapter} currentUser={user}>
    {children}
  </FeedtackProvider>
) : (
  children
)}
```

## 5. Error handling

Always pass `onError` in production to catch adapter failures:

```tsx
<FeedtackProvider
  adapter={adapter}
  currentUser={user}
  onError={(err) => {
    // Send to your error tracking service
    Sentry.captureException(err);
  }}
>
```
